# Notifications & Watchers Implementation Plan

> **⚠️ IMPORTANT FOR AGENTS**: This plan follows the architecture patterns documented in `AGENTS.md`. Before implementing, familiarize yourself with:
> - The 4-layer frontend pattern: Repository → Service → Store → Component
> - BullMQ/Redis async processing patterns
> - Supabase RLS security requirements
> - Real-time subscription patterns
>
> **If you find conflicts between this plan and the codebase, trust the codebase and update this plan.**

## Overview
This plan outlines the implementation of a comprehensive notification system with watcher functionality for the Sentinel application. Users will be able to "watch" organizations and meetings, configure notification preferences, and receive **in-app notifications** for relevant events.

**Future-proofing**: The architecture is designed to support **push notifications** (web push, mobile) in the future without major refactoring. See the "Push Notification Readiness" section for details.

## 1. Database Schema Changes

### 1.1 Create Watchers Table
**File**: `supabase/migrations/YYYYMMDDHHMMSS_create_watchers_table.sql`

Create a new `watchers` table to track which users are watching which organizations/meetings:

```sql
CREATE TABLE "public"."watchers" (
    "id" bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL PRIMARY KEY,
    "user_id" uuid NOT NULL,
    "dashboard_id" bigint NOT NULL,
    "organization_id" bigint NULL,
    "meeting_id" bigint NULL,
    "created_at" timestamp with time zone NOT NULL DEFAULT now(),

    CONSTRAINT "watchers_user_id_fkey"
        FOREIGN KEY (user_id)
        REFERENCES users(id)
        ON UPDATE CASCADE ON DELETE CASCADE,

    CONSTRAINT "watchers_dashboard_id_fkey"
        FOREIGN KEY (dashboard_id)
        REFERENCES dashboards(id)
        ON UPDATE CASCADE ON DELETE CASCADE,

    CONSTRAINT "watchers_organization_id_fkey"
        FOREIGN KEY (organization_id)
        REFERENCES organizations(id)
        ON UPDATE CASCADE ON DELETE CASCADE,

    CONSTRAINT "watchers_meeting_id_fkey"
        FOREIGN KEY (meeting_id)
        REFERENCES meetings(id)
        ON UPDATE CASCADE ON DELETE CASCADE,

    -- Either watching an organization OR a meeting, not both
    CONSTRAINT "watchers_org_or_meeting_check"
        CHECK (
            (organization_id IS NOT NULL AND meeting_id IS NULL) OR
            (organization_id IS NULL AND meeting_id IS NOT NULL)
        )
);

-- Unique constraint: user can only watch an org/meeting once
CREATE UNIQUE INDEX watchers_user_org_unique
    ON public.watchers (user_id, organization_id)
    WHERE meeting_id IS NULL;

CREATE UNIQUE INDEX watchers_user_meeting_unique
    ON public.watchers (user_id, meeting_id)
    WHERE organization_id IS NULL;

-- Index for faster lookups
CREATE INDEX watchers_organization_id_idx ON public.watchers (organization_id);
CREATE INDEX watchers_meeting_id_idx ON public.watchers (meeting_id);
CREATE INDEX watchers_user_id_idx ON public.watchers (user_id);

-- Enable RLS
ALTER TABLE "public"."watchers" ENABLE ROW LEVEL SECURITY;

-- RLS Policies: Users can only manage their own watchers
CREATE POLICY "Users can view their own watchers"
    ON "public"."watchers"
    FOR SELECT
    TO authenticated
    USING (user_id = auth.uid());

CREATE POLICY "Users can create their own watchers"
    ON "public"."watchers"
    FOR INSERT
    TO authenticated
    WITH CHECK (user_id = auth.uid());

CREATE POLICY "Users can delete their own watchers"
    ON "public"."watchers"
    FOR DELETE
    TO authenticated
    USING (user_id = auth.uid());

-- Grant permissions
GRANT SELECT, INSERT, DELETE ON TABLE "public"."watchers" TO "authenticated";
GRANT SELECT, INSERT, DELETE ON TABLE "public"."watchers" TO "service_role";
```

### 2.2 Create Notification Settings Service
**File**: `functions/src/notification-settings/notification-settings.service.ts`

```typescript
import { Injectable, Logger } from "@nestjs/common";
import { SupabaseClient } from "@supabase/supabase-js";
import { SupabaseService } from "../supabase/supabase.service";
import { Database, Tables } from "../types/supabase-generated.types";

export interface NotificationSettingsData {
    enabledNotificationTypes: string[];
    autoWatchNewMeetings?: boolean;
}

@Injectable()
export class NotificationSettingsService {
    private logger = new Logger(NotificationSettingsService.name);
    private readonly supabase: SupabaseClient<Database>;

    constructor(supabaseService: SupabaseService) {
        this.supabase = supabaseService.supabase;
    }

    /**
     * Get notification settings for a user at a specific scope
     * Returns default settings if none exist
     */
    async getNotificationSettings(
        userId: string,
        dashboardId: number | null,
        organizationId: number | null,
        meetingId: number | null
    ): Promise<NotificationSettingsData> {
        let query = this.supabase
            .from("notification_settings")
            .select("*")
            .eq("user_id", userId);

        if (dashboardId !== null) {
            query = query.eq("dashboard_id", dashboardId);
        } else {
            query = query.is("dashboard_id", null);
        }

        if (organizationId !== null) {
            query = query.eq("organization_id", organizationId);
        } else {
            query = query.is("organization_id", null);
        }

        if (meetingId !== null) {
            query = query.eq("meeting_id", meetingId);
        } else {
            query = query.is("meeting_id", null);
        }

        const { data, error } = await query.maybeSingle();

        if (error) {
            this.logger.error("Error fetching notification settings:", error);
            throw new Error(`Error fetching notification settings: ${error.message}`);
        }

        // Return default settings if none exist
        if (!data) {
            return {
                enabledNotificationTypes: [],
                autoWatchNewMeetings: false,
            };
        }

        return data.settings as NotificationSettingsData;
    }

    /**
     * Check if a user has a specific notification type enabled at dashboard level
     */
    async hasNotificationEnabled(
        userId: string,
        dashboardId: number,
        notificationType: string
    ): Promise<boolean> {
        const settings = await this.getNotificationSettings(
            userId,
            dashboardId,
            null,
            null
        );

        return settings.enabledNotificationTypes.includes(notificationType);
    }

    /**
     * Check if a user has auto-watch enabled
     */
    async hasAutoWatchEnabled(
        userId: string,
        dashboardId: number
    ): Promise<boolean> {
        const settings = await this.getNotificationSettings(
            userId,
            dashboardId,
            null,
            null
        );

        return settings.autoWatchNewMeetings === true;
    }
}
```

### 2.3 Update Webhooks Service
**File**: `functions/src/webhooks/webhooks.service.ts`

Add new webhook handlers for meeting creation and log insertion:

```typescript
/**
 * Handle new meeting insertion
 * 1. Get all watchers of the parent organization
 * 2. For each watcher, check their notification settings
 * 3. If "notify on new meeting" is enabled, create a notification
 * 4. If "auto watch new meetings" is enabled, add them as a watcher
 */
async handleMeetingInsert(payload: any): Promise<void> {
    this.logger.log("Handling meeting insert webhook");

    const meetingId = payload.record.id;
    const organizationId = payload.record.organization_id;
    const meetingName = payload.record.name;
    const meetingDate = payload.record.meeting_date;

    // Get the organization to find dashboard_id
    const { data: org, error: orgError } = await this.supabase
        .from("organizations")
        .select("dashboard_id, name")
        .eq("id", organizationId)
        .single();

    if (orgError || !org) {
        this.logger.error("Error fetching organization:", orgError);
        return;
    }

    const dashboardId = org.dashboard_id;
    const organizationName = org.name;

    // Get all watchers of this organization
    const orgWatchers = await this.watchersService.getOrganizationWatchers(organizationId);

    this.logger.log(`Found ${orgWatchers.length} watchers for organization ${organizationId}`);

    // Process each watcher
    for (const watcher of orgWatchers) {
        const userId = watcher.user_id;

        // Check if user has "notify on new meeting" enabled
        const shouldNotify = await this.notificationSettingsService.hasNotificationEnabled(
            userId,
            dashboardId,
            "meeting_created"
        );

        if (shouldNotify) {
            this.logger.log(`Creating notification for user ${userId}`);

            // Create notification
            await this.supabase.from("notifications").insert({
                type: "meeting_created",
                user_id: userId,
                log_id: null, // No log yet
                additional_context: {
                    meeting_id: meetingId,
                    meeting_name: meetingName,
                    meeting_date: meetingDate,
                    organization_id: organizationId,
                    organization_name: organizationName,
                },
            });
        }

        // Check if user has "auto watch new meetings" enabled
        const shouldAutoWatch = await this.notificationSettingsService.hasAutoWatchEnabled(
            userId,
            dashboardId
        );

        if (shouldAutoWatch) {
            this.logger.log(`Auto-watching meeting for user ${userId}`);

            try {
                await this.watchersService.addMeetingWatcher(
                    userId,
                    dashboardId,
                    meetingId
                );
            } catch (error) {
                // Ignore duplicate errors (user may already be watching)
                this.logger.warn(`Could not auto-watch meeting: ${error.message}`);
            }
        }
    }
}

/**
 * Handle new log insertion
 * Check if it's a comment, and notify watchers if needed
 */
async handleLogInsert(payload: any): Promise<void> {
    this.logger.log("Handling log insert webhook");

    const logId = payload.record.id;
    const logType = payload.record.type;
    const meetingId = payload.record.meeting_id;
    const organizationId = payload.record.org_id;
    const createdBy = payload.record.created_by;

    // Only process comment logs
    if (logType !== "comment") {
        this.logger.log(`Skipping non-comment log type: ${logType}`);
        return;
    }

    // Determine the context (meeting or organization)
    let watchers: Tables<"watchers">[] = [];
    let dashboardId: number;
    let contextInfo: any = {};

    if (meetingId) {
        // Get meeting info
        const { data: meeting, error: meetingError } = await this.supabase
            .from("meetings")
            .select("organization_id, name, meeting_date")
            .eq("id", meetingId)
            .single();

        if (meetingError || !meeting) {
            this.logger.error("Error fetching meeting:", meetingError);
            return;
        }

        // Get organization info
        const { data: org, error: orgError } = await this.supabase
            .from("organizations")
            .select("dashboard_id, name")
            .eq("id", meeting.organization_id)
            .single();

        if (orgError || !org) {
            this.logger.error("Error fetching organization:", orgError);
            return;
        }

        dashboardId = org.dashboard_id;
        contextInfo = {
            meeting_id: meetingId,
            meeting_name: meeting.name,
            organization_id: meeting.organization_id,
            organization_name: org.name,
        };

        // Get meeting watchers
        watchers = await this.watchersService.getMeetingWatchers(meetingId);
    } else if (organizationId) {
        // Get organization info
        const { data: org, error: orgError } = await this.supabase
            .from("organizations")
            .select("dashboard_id, name")
            .eq("id", organizationId)
            .single();

        if (orgError || !org) {
            this.logger.error("Error fetching organization:", orgError);
            return;
        }

        dashboardId = org.dashboard_id;
        contextInfo = {
            organization_id: organizationId,
            organization_name: org.name,
        };

        // Get organization watchers
        watchers = await this.watchersService.getOrganizationWatchers(organizationId);
    } else {
        this.logger.warn("Log has neither meeting_id nor org_id");
        return;
    }

    this.logger.log(`Found ${watchers.length} watchers for log ${logId}`);

    // Notify each watcher (except the comment author)
    for (const watcher of watchers) {
        const userId = watcher.user_id;

        // Don't notify the user who created the comment
        if (userId === createdBy) {
            continue;
        }

        // Check if user has "notify on comment" enabled
        const shouldNotify = await this.notificationSettingsService.hasNotificationEnabled(
            userId,
            dashboardId,
            "comment_added"
        );

        if (shouldNotify) {
            this.logger.log(`Creating comment notification for user ${userId}`);

            await this.supabase.from("notifications").insert({
                type: "comment_added",
                user_id: userId,
                log_id: logId,
                additional_context: contextInfo,
            });
        }
    }
}
```

```typescript
import { supabase } from "@/lib/supabase.lib";
import { Tables, TablesInsert } from "@/types/supabase-generated.types";

export type WatcherDTO = Tables<"watchers">;

export class WatchersRepository {
    private static watchers = () => supabase.from("watchers");

     * Check if a user is watching a meeting
     */
    public static async isWatchingMeeting(

     */
    public static async addOrganizationWatcher(

            .select("*")
            .single();

        if (error) {
            throw getRepositoryError(
                error,
                ErrorVerb.Create,
                ErrorNoun.Watchers,
                false,
                status
            );
        }

        return data;
    }

    /**
     * Add a watcher for a meeting
     */
    public static async addMeetingWatcher(
        userId: string,
        dashboardId: number,
        meetingId: number
    ): Promise<WatcherDTO> {
        const { data, error, status } = await this.watchers()
            .insert({
                user_id: userId,
                dashboard_id: dashboardId,

                meeting_id: meetingId,

        if (error) {
            throw getRepositoryError(
                error,
                ErrorVerb.Create,
                ErrorNoun.Watchers,
                false,
                status
            );
        }

        return data;
    }

    /**
     * Remove a watcher for an organization
     */
    public static async removeOrganizationWatcher(
        userId: string,
        organizationId: number
    ): Promise<void> {
        const { error, status } = await this.watchers()
            .delete()
            .eq("user_id", userId)
            .eq("organization_id", organizationId)
            .is("meeting_id", null);

        if (error) {
            throw getRepositoryError(
                error,
                ErrorVerb.Delete,
                ErrorNoun.Watchers,
                false,
                status
            );
        }
    }

    /**
     * Remove a watcher for a meeting
     */
    public static async removeMeetingWatcher(
        userId: string,
        meetingId: number
    ): Promise<void> {
        const { error, status } = await this.watchers()
            .delete()
            .eq("user_id", userId)
            .eq("meeting_id", meetingId)
            .is("organization_id", null);

        if (error) {
            throw getRepositoryError(
                error,
                ErrorVerb.Delete,
                ErrorNoun.Watchers,
                false,
                status
            );
        }
    }

    /**
     * Subscribe to watchers for a user in a dashboard
     */
    public static subscribeToWatchers(
        userId: string,
        dashboardId: number,
        onPayload: (payload: WatcherDTO[], type: "initial" | "insert" | "delete") => void
    ): () => void {
        return createSubscription(
            `watchers:${userId}:${dashboardId}`,
            "watchers",
            `user_id=eq.${userId},dashboard_id=eq.${dashboardId}`,
            async () => {
                return await this.getWatchersForUserInDashboard(userId, dashboardId);
            },
            (type, payload) => {
                if (type === "initial") {
                    onPayload(payload as WatcherDTO[], "initial");
                } else if (type === "INSERT") {
                    onPayload([payload.new as WatcherDTO], "insert");
                } else if (type === "DELETE") {
                    onPayload([payload.old as WatcherDTO], "delete");
                }
            }
        );
    }
}
```

```typescript
import { immer } from "zustand/middleware/immer";
import { createWithEqualityFn } from "zustand/traditional";
import deepEqual from "fast-deep-equal";
import { useEffect } from "react";

export interface WatchersStoreState {
    // Map of organizationId/meetingId to watcher record
    organizationWatchers: Record<number, IWatcher>;
    meetingWatchers: Record<number, IWatcher>;
    isLoading: boolean;
    error: string | null;
}

export interface WatchersStoreActions {
    subscribeToWatchers: (userId: string, dashboardId: number) => () => void;
    toggleOrganizationWatch: (
        userId: string,
        dashboardId: number,
        organizationId: number
    ) => Promise<void>;
    toggleMeetingWatch: (
        userId: string,
        dashboardId: number,
        meetingId: number
    ) => Promise<void>;
    isWatchingOrganization: (organizationId: number) => boolean;
    isWatchingMeeting: (meetingId: number) => boolean;
    resetStore: () => void;
}

const defaultState: WatchersStoreState = {
    organizationWatchers: {},
    meetingWatchers: {},
    isLoading: true,
    error: null,
};

export const useWatchersStore = createWithEqualityFn<
    WatchersStoreState & WatchersStoreActions
>()(
    immer((set, get) => ({
        ...defaultState,

        subscribeToWatchers: (userId: string, dashboardId: number) => {
            set({ isLoading: true, error: null });

            return WatchersService.subscribeToWatchers(
                userId,
                dashboardId,
                (watchers, type) => {
                    set((state) => {
                        if (type === "initial") {
                            // Reset and populate
                            state.organizationWatchers = {};
                            state.meetingWatchers = {};

                            watchers.forEach((watcher) => {
                                if (watcher.organizationId) {
                                    state.organizationWatchers[watcher.organizationId] =
                                        watcher;
                                } else if (watcher.meetingId) {
                                    state.meetingWatchers[watcher.meetingId] = watcher;
                                }
                            });

                            state.isLoading = false;
                        } else if (type === "insert") {
                            watchers.forEach((watcher) => {
                                if (watcher.organizationId) {
                                    state.organizationWatchers[watcher.organizationId] =
                                        watcher;
                                } else if (watcher.meetingId) {
                                    state.meetingWatchers[watcher.meetingId] = watcher;
                                }
                            });
                        } else if (type === "delete") {
                            watchers.forEach((watcher) => {
                                if (watcher.organizationId) {
                                    delete state.organizationWatchers[
                                        watcher.organizationId
                                    ];
                                } else if (watcher.meetingId) {
                                    delete state.meetingWatchers[watcher.meetingId];
                                }
                            });
                        }
                    });
                }
            );
        },

        toggleOrganizationWatch: async (
            userId: string,
            dashboardId: number,
            organizationId: number
        ) => {
            const isCurrentlyWatching = get().isWatchingOrganization(organizationId);

            try {
                await WatchersService.toggleOrganizationWatch(
                    userId,
                    dashboardId,
                    organizationId,
                    isCurrentlyWatching
                );
            } catch (error: any) {
                set({ error: error.message });
                throw error;
            }
        },

        toggleMeetingWatch: async (
            userId: string,
            dashboardId: number,
            meetingId: number
        ) => {
            const isCurrentlyWatching = get().isWatchingMeeting(meetingId);

            try {
                await WatchersService.toggleMeetingWatch(
                    userId,
                    dashboardId,
                    meetingId,
                    isCurrentlyWatching
                );
            } catch (error: any) {
                set({ error: error.message });
                throw error;
            }
        },

        isWatchingOrganization: (organizationId: number) => {
            return organizationId in get().organizationWatchers;
        },

        isWatchingMeeting: (meetingId: number) => {
            return meetingId in get().meetingWatchers;
        },

        resetStore: () => {
            set(defaultState);
        },
    })),
    deepEqual
);
```

```typescript
    );

    // Mark them all as read

    });
}, [organizationId, notifications, markNotificationAsRead]);
```

## 9. Push Notification Readiness

The current implementation is designed for **in-app notifications only**, but the architecture is **future-proof** for adding push notifications (web push API, mobile push, etc.) without major refactoring.

### 9.1 Why the Current Architecture Supports Push Notifications

#### Database Schema Is Already Extensible
The `notifications` table uses:
- **JSONB `additional_context`** - Can store push-specific data (device tokens, payload)
- **Enum `notification_types`** - Easy to add new types
- **Nullable `log_id`** - Notifications aren't tied to activity logs

**What you'd add for push**:
```sql
-- New table for push subscriptions
CREATE TABLE "public"."push_subscriptions" (
    "id" bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL PRIMARY KEY,
    "user_id" uuid NOT NULL REFERENCES users(id),
    "endpoint" text NOT NULL,
    "p256dh_key" text NOT NULL,
    "auth_key" text NOT NULL,
    "user_agent" text,
    "created_at" timestamp with time zone NOT NULL DEFAULT now()
);

-- OR add columns to notification_settings
ALTER TABLE notification_settings
ADD COLUMN "push_enabled" boolean DEFAULT false,
ADD COLUMN "push_subscription" jsonb;
```

#### Notification Settings Are Delivery-Agnostic
Current `notification_settings.settings` JSONB:
```json
{
  "enabledNotificationTypes": ["meeting_created", "comment_added"],
  "autoWatchNewMeetings": true
}
```

**Easy to extend**:
```json
{
  "enabledNotificationTypes": ["meeting_created", "comment_added"],
  "autoWatchNewMeetings": true,
  "deliveryChannels": {
    "meeting_created": ["in-app", "push"],
    "comment_added": ["in-app", "push", "email"]
  },
  "pushEnabled": true,
  "emailEnabled": false
}
```

#### Backend Webhooks Are Already Decoupled
The webhook handlers (`handleMeetingInsert`, `handleLogInsert`) create notification **records** in the database. They don't know or care how notifications are delivered.

**To add push, you'd just**:
1. Keep existing webhook logic (creates notification records)
2. Add a new webhook trigger or listener on the `notifications` table
3. When a notification is inserted, send push notification asynchronously

**Example with BullMQ**:
```typescript
// New processor: functions/src/push/push.processor.ts
@Processor({ name: "push-notification-queue" })
export class PushProcessor extends WorkerHost {
    async process(job: Job<{ notificationId: string }>) {
        const notification = await this.getNotification(job.data.notificationId);
        const user = await this.getUser(notification.user_id);
        const subscriptions = await this.getPushSubscriptions(user.id);

        for (const subscription of subscriptions) {
            await this.sendWebPush(subscription, {
                title: this.getNotificationTitle(notification),
                body: this.getNotificationBody(notification),
                data: notification.additional_context,
            });
        }
    }
}

// Trigger from webhook or database trigger
@Post("/notifications/insert")
async handleNotificationInsert(@Body() payload: any) {
    const notificationId = payload.record.id;

    // Add to push queue (non-blocking)
    await this.pushQueue.add("send-push", { notificationId });
}
```

#### Frontend Service Layer Is Already Abstracted
The `NotificationsService` already converts DTOs to domain models. Push notifications would just be another source:

**Current flow**:
```
Database INSERT → Realtime → Repository → Service → Store → UI
```

**With push**:
```
Database INSERT → Realtime → Repository → Service → Store → UI
              ↓
            Webhook → BullMQ → Push Processor → Web Push API → Browser/Device
```

The frontend doesn't need to change because:
- Realtime subscriptions still work for when the app is open
- Push notifications wake the app when closed
- Both ultimately create the same notification records

#### Notification Types Are Semantic, Not Delivery-Specific
Current types: `meeting_created`, `comment_added`, `meeting_document_added`

These describe **what happened**, not **how to notify**. This is perfect for push because:
- Same notification type can trigger multiple delivery methods
- Push payload can be customized per type
- No refactoring needed

### 9.2 Recommended Approach for Adding Push Notifications

When you're ready to implement push notifications, follow this order:

#### Phase 1: Database & Subscription Storage
1. Create `push_subscriptions` table (or extend `notification_settings`)
2. Store web push subscriptions (endpoint, keys)
3. Add RLS policies for user access

#### Phase 2: Backend Push Infrastructure
1. Create new module: `functions/src/push/`
2. Implement web push service (using `web-push` npm package)
3. Create BullMQ queue: `push-notification-queue`
4. Create processor that sends push notifications
5. Add webhook/trigger on `notifications` INSERT to enqueue push jobs

#### Phase 3: Frontend Push Subscription
1. Request notification permission in browser
2. Subscribe to push notifications (Web Push API)
3. Send subscription to backend (new endpoint)
4. Store subscription in database
5. Add UI toggle in notification settings

#### Phase 4: Service Worker
1. Create service worker to handle push events
2. Show notification using Notification API
3. Handle notification clicks (navigate to relevant page)
4. Sync with realtime subscriptions (avoid duplicates)

### 9.3 Migration Path

**No breaking changes needed**:
- Existing notifications continue to work
- Push is purely additive
- Users opt-in to push (default: off)
- Can have in-app only, push only, or both

**Code changes**:
- ~0% change to existing notification logic
- ~5 new files for push infrastructure
- 1 database migration
- Frontend: 1 service worker + subscription UI

### 9.4 Push Notification Libraries

**Backend**:
- `web-push` - Web Push Protocol implementation
- BullMQ - Already in the stack for async processing

**Frontend**:
- Native Web Push API (no library needed)
- Service Worker API (built into browsers)

**Example subscription**:
```typescript

const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: publicVapidKey,

    method: 'POST',
    body: JSON.stringify(subscription),
});
```

### 9.5 Current Implementation Checklist for Push-Readiness

✅ **Already push-ready**:
- Database uses JSONB for extensibility

- Backend uses async processing (BullMQ)
- Frontend uses semantic notification types

❌ **Not needed yet** (add when implementing push):

**Verdict**: The current architecture is **fully ready** for push notifications. When you want to add them, it's a clean extension, not a refactor.

### 10.1 Notification Behavior

**Q**: Should users receive notifications for meetings/comments that were created/added before they started watching?
✅ **DECISION**: No, only notify for events that occur after they start watching.

**Q**: When a user unwatches an organization, should they be automatically unwatched from all meetings in that organization?
✅ **DECISION**: No, keep meeting watches independent. However, **display a notification/toast** to the user when they unwatch an organization informing them: "You are still watching X meetings in this organization. Unwatch those meetings individually if desired."

**Q**: Should there be a "mark all as read" button in the notification dropdown?
✅ **DECISION**: Yes, add to NotificationBell component. Additionally, users should be able to **dismiss notifications without opening them** (e.g., X button on each notification item).

**Implementation notes**:

- Toast message when unwatching org with active meeting watches

### 10.6 Data Cleanup

**Q**: Should old read notifications be automatically deleted after a certain period?
✅ **DECISION**: Yes, delete notifications immediately after they are marked as read (if there's no reason to keep them).

**Rationale**: Notifications are ephemeral - once read and dismissed, they serve no purpose. Keeping the table small improves performance.

**Implementation**:
- When `markNotificationAsRead()` is called, immediately delete the notification
- When user navigates to org/meeting and notifications auto-mark as read, delete them
- When user clicks "dismiss" (X button), delete immediately
- When user clicks "mark all as read", delete all in one query

**Cleanup query**:
```typescript
// In repository
public static async deleteNotification(notificationId: string): Promise<void> {
    const { error } = await this.notifications()
        .delete()
        .eq("id", notificationId);

    if (error) throw getRepositoryError(error, ErrorVerb.Delete, ErrorNoun.Notifications);
}

// Or batch delete
public static async deleteNotifications(notificationIds: string[]): Promise<void> {
    const { error } = await this.notifications()
        .delete()
        .in("id", notificationIds);

    if (error) throw getRepositoryError(error, ErrorVerb.Delete, ErrorNoun.Notifications);
}
```

**Update store actions**:
```typescript
markNotificationAsRead: async (id: string) => {
    await NotificationsService.deleteNotification(id); // Changed from update to delete
    set((state) => {
        delete state.notifications[id];
    });
}
```

## Notes for the Executing Agent

### Architecture & Patterns (See ARCHITECTURE.md)

**CRITICAL**: Before implementing, read `ARCHITECTURE.md` thoroughly. Key patterns to follow:

#### Frontend: 4-Layer Architecture
```
Component → Store → Service → Repository → Supabase
```
- **Repository**: Direct database access, returns DTOs
- **Service**: Business logic, converts DTOs to domain models (IModel types)
- **Store**: Zustand + Immer state management, manages subscriptions
- **Component**: UI rendering, uses sync hooks (useSyncXxx)

#### Backend: NestJS Modules
- Use **dependency injection** for all services
- Inject `SupabaseService` for database access
- Follow existing module structure in `functions/src/`

#### Real-time Subscriptions
- Use `createSubscription` helper from `_subscriptionManager.ts`
- Always load initial data, then stream updates
- Return unsubscribe function for cleanup
- Use sync hooks in components (e.g., `useSyncWatchers`)

#### Error Handling
- Frontend: Use `getRepositoryError` from `_repositoryErrors.ts`
- Backend: Log errors clearly, throw user-friendly messages
- Never expose internal errors to users

#### Async Processing
- Long-running tasks MUST use **BullMQ queues**
- See `scraper.service.ts` and `scraper.processor.ts` for examples
- Don't block HTTP requests with slow operations
- If notification creation becomes slow, move to a queue

### Database Requirements

- All migrations in `supabase/migrations/YYYYMMDDHHMMSS_description.sql`
- **ALWAYS enable RLS** on new tables
- Create appropriate policies (users can only see their own data)
- Use foreign keys with `ON DELETE CASCADE` where appropriate
- Add indexes for foreign keys and frequently queried columns
- Enable `REPLICA IDENTITY FULL` for tables with realtime subscriptions

### Code Standards

- **TypeScript**: Use strict mode, leverage auto-generated Supabase types
- **Naming**: Follow conventions in ARCHITECTURE.md
  - `.repository.ts`, `.service.ts`, `.store.ts`, `.tsx`
  - `useSyncXxx()` for subscription hooks
  - `IModel` for domain types, `ModelDTO` for database types
- **State Management**: Zustand with Immer, use `deepEqual` for stores
- **UI**: Chakra UI v3 components only
- **Icons**: Lucide React

### Security Checklist

- [ ] RLS enabled on all new tables
- [ ] Policies restrict access to user's own data
- [ ] Service role key never exposed to frontend
- [ ] Webhooks validate payload before processing
- [ ] Push subscriptions (future) require user auth

### Testing Checklist

### Common Pitfalls to Avoid

1. **Forgetting RLS**: All new tables MUST have RLS enabled
2. **Skipping layers**: Don't call Repository from Components
3. **Mutating state**: Use Immer's draft pattern in stores
4. **Memory leaks**: Always return cleanup functions from subscriptions
5. **Blocking operations**: Use BullMQ for slow tasks (> 5 seconds)
6. **Hardcoding**: Use environment variables for config

### When to Use BullMQ

**Use BullMQ if**:
- Task takes > 5 seconds
- Task can fail and needs retry logic
- Task is not user-facing (background processing)
- Task needs to be rate-limited

**Don't use BullMQ if**:
- Simple database query (< 1 second)
- User expects immediate response
- Real-time synchronization needed
